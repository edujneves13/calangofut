# Fase 1 — Parte B: Banco e regras de acesso — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Criar o banco do Supabase (tabelas, restrições, RLS) e a camada `src/data/` que lê e grava cada ação da quarta, testados contra um Supabase local.

**Architecture:** Esquema em migrações SQL versionadas (`supabase/migrations/`), testadas com pgTAP (`supabase test db`). `src/data/` são funções pequenas que recebem o cliente Supabase como parâmetro (sem depender de Vite) e devolvem os tipos de `src/logic/`. Testes de integração Vitest rodam contra o Supabase local, logados como um admin de teste criado no `seed.sql`.

**Tech Stack:** Supabase CLI (devDependency `supabase`, via `npx`), Docker (para o Supabase local), Postgres 15 + pgTAP, `@supabase/supabase-js` v2, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-19-pelada-sorteio-design.md`
**Depende de:** Parte A (`docs/superpowers/plans/2026-11-19-fase1-logica.md`) — tipos `Jogador`, `Time`, `Jogo`, `FormatoId`.

## Decisões deste plano que a spec não cobre

1. **4ª tabela `configuracoes`** (uma linha só) para a tela de Configurações: formato padrão por nº de times, duração, horário e local padrão. A spec fala em "três tabelas", mas a tela de Configurações precisa salvar em algum lugar.
2. **`peladas.duracao_min` em coluna**, não dentro de um `config` JSON. Tamanho do time continua fixo em 5 no código (`TAMANHO_TIME`).
3. **Nome único entre jogadores ativos** (comparado sem acento, maiúsculas e espaços extras). Atende o estado "nome duplicado" da tela de Jogadores e evita o casamento ambíguo. Desativado pode repetir nome.
4. **Uma pelada por data** (`unique (data)`).
5. **Fuso `America/Fortaleza`** (João Pessoa) para calcular a próxima quarta.

## Global Constraints

- RLS ligado em **todas** as tabelas. Logado (`authenticated`) lê e grava tudo; deslogado (`anon`) não vê nada.
- A `service_role` key nunca entra no projeto (nem em teste, nem em `.env.example`). Testes usam a anon key + login do admin de teste.
- `.env.local` fora do git. Variáveis: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.
- Cadastro público desligado (`enable_signup = false` local; mesma opção no painel do projeto real).
- Jogador nunca é apagado: desativar (`ativo = false`). Apagar jogador com presença registrada falha.
- `src/data/` não importa React nem `import.meta.env`; recebe `SupabaseClient` por parâmetro.
- Nomes de tabelas e colunas em português, `snake_case`, como na spec.

## Review Focus

1. **Recarregar a página ou tocar duas vezes em "abrir pelada"** → continua existindo uma pelada só para a data. Teste na Task 5.
2. **Cadastrar "Léo" quando já existe "leo" ativo** → erro `nome-duplicado` (a tela mostra o aviso); com o antigo desativado, cadastra. Teste na Task 2 (banco) e Task 4 (`src/data`).
3. **Apagar jogador que já jogou** → banco recusa; desativar funciona e as peladas antigas continuam lendo o nome. Teste na Task 2.
4. **Alguém com a URL e a anon key, sem login** → zero linhas em todas as tabelas, inclusive estrelas. Teste na Task 3.
5. **Quarta às 23:30 em João Pessoa (já é quinta em UTC)** → próxima pelada ainda é essa quarta; quinta 00:10 → quarta seguinte. Teste na Task 5.
